# Tax Form Annotation Walkthrough Script

| Time | Beat | Script / Action |
|---|---|---|
| 0:00–0:30 | The problem | **Visual**: Blank 1040 PDF side-by-side with a nested JSON dataset.<br>**Audio**: "Printing nested taxpayer data into arbitrary tax forms is brittle. Every platform builds its own hardcoded renderer. This project introduces a machine-readable JSON specification that separates the 'where and how' of form fields from the 'what' of tax data, allowing any third-party renderer to fill forms automatically." |
| 0:30–1:45 | One annotation end to end | **Visual**: Show `annotations/f1040-2024.json`. Highlight one FieldAnnotation (`box`, `type`, `value`, `format`). Explain top-left coordinate system.<br>**Audio**: "Here's one annotation. It declares an ID, a top-left origin box in PDF points, the field type, and formatting rules. We use exact coordinates instead of AcroForm names because form field names change yearly, are opaque, and fail on scanned documents. The coordinates are the primary anchor." |
| 1:45–2:30 | Referencing deeply nested data | **Visual**: Show `value: "$.income.w2[0].wages"`. Open `resolver.py`.<br>**Audio**: "Values are mapped using a strict subset of JSONPath. It supports child access, arrays, and deep scans. Notice we explicitly exclude filter expressions. This guarantees the format is portable across languages and prevents code-execution vulnerabilities." |
| 2:30–3:15 | Repeating groups | **Visual**: Show Schedule B JSON annotation with `kind: group`. Point out `overflowStrategy`.<br>**Audio**: "For repeating rows like Schedule B payers, we define a group. It specifies a `rowHeight`, `maxRows`, and an `overflowStrategy`. If the dataset has more rows than the form can fit, the system automatically triggers a 'statement' overflow, placing a 'See Attached' text in a designated overflow target field." |
| 3:15–4:15 | Live demo | **Visual**: Run `flask --app app run`. Open browser. Click 'Render'. Show output PDF. Add `?debug=1` to the URL. Show colored bounding boxes.<br>**Audio**: "Let's see it in action. Passing our dataset through the pipeline yields a perfectly filled 1040. If we add `?debug=1` to the URL, the renderer draws the exact bounding box for every declared annotation, proving the specification is visually precise." |
| 4:15–5:00 | Decisions & Enhancements | **Visual**: Flash the Decisions table. Show the Future Enhancements list in `SPEC.md`.<br>**Audio**: "We made several key decisions: no tax compute logic in the schema, and a representative subset of annotations to prove the model.
